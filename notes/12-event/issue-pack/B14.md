# Round-trip an Office Kit pack and countersign with the engineer key

A capture pack can be reviewed, countersigned on P2 and verified offline on P1/P3 without changing its evidence.

## Ownership and deliverable

Own **officekit/, record/ approval and QR verification**. You are not alone in the codebase: preserve others' changes. Alwin owns UI, Sabari camera/geometry, Melvin shared types/build/rules/trust. Request a handoff before editing another package or frozen contract.

## Work

- Export a documented .sariya.zip containing canonical payload, detached capture signature, evidence and manifest; use Android document/share APIs. Import received files with ACTION_OPEN_DOCUMENT or granted URIs, not raw directory enumeration of Office Kit-owned files.
- Validate sizes, paths, hashes, schema and capture signature before showing a trusted record. Reject zip traversal/oversize/missing evidence; import idempotently.
- Engineer approval signs a domain-separated envelope containing capture payload hash, capture-signature binding, approval decision, record revision and enrolled key identity. Authenticate the approval operation using BiometricPrompt; cancel means no signature.
- Return the detached approval through Office Kit and merge it only into the exact immutable capture it references. Persist both signatures and verification states.
- Generate a compact verification QR with hashes/key IDs/signatures or a defined local-record lookup; on a new P3 explain whether the full pack is required. Verify against enrolled keys, never trust embedded keys automatically.
- Prove offline compute independently from Office Kit local Wi-Fi requirements; no cloud endpoint or INTERNET permission required by Sariya’s core.
- Implement the ReviewRequest artifact/response path agreed in B01: reference capture hash/member, requested view/note, origin identity/status. Import idempotently as a pending request and link the subsequent new record; a request never alters or approves the old record.

## Acceptance

- [ ] P1 -> laptop -> P2 -> laptop -> P1 yields byte-identical capture payload. P3 verifies the enrolled two-key chain after receiving any required pack.
- [ ] Fingerprint cancellation, wrong key, changed image/spec, malformed zip and mismatched approval hash cannot display two valid signatures.
- [ ] Imported document access works on Android 16 after app restart/update; revoked URI permission asks to select again.

**Loaner check:** Time a genuine Office Kit round trip and fingerprint approval on the three loaners. Attempt a changed-byte pack and confirm visible rejection.

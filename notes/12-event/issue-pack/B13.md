# Build the engineer review desk and Office Kit file handoff UX

The engineer can inspect a record on a phone mirrored to the laptop and deliberately approve or request another view.

**Owner:** @AlwinSunil · **Phase:** CP2 · **Budget:** 2 focused person-hours (estimate; excludes idle training/download time)
**Control and current gate times:** [CONTROL.md](CONTROL.md)
**Prerequisites / integration dependencies:** [B01](B01.md), [B09](B09.md)
Work against B01 fixtures while a service dependency is being built; acceptance still needs the real service. The control issue defines the explicit manual/gated fallback path. Do not close an unproven automatic feature just because the fallback shipped.

## Ownership and deliverable

Own **ui/review/, ui/transfers/; consumes record and officekit contracts**. You are not alone in the codebase: preserve others' changes. Alwin owns UI, Sabari camera/geometry, Melvin shared types/build/rules/trust. Request a handoff before editing another package or frozen contract.

## Work

- Build against B12/B14 fake adapters first, so trust implementation does not block design. Show frozen photo/overlay, drawing, numbers/bands, source, manual fields, missing checks, both signer states and record revision.
- Create Export pack / Open received pack / Return signed pack actions with visible states, hashes and error recovery. Office Kit is an external app and file bridge; do not invent an Office Kit SDK or hidden transfer status.
- Explain the real sequence P1 export -> Office Kit laptop -> P2 open -> review -> fingerprint -> return. The laptop is a mirror/review desk, not a third private key or a backend service.
- Keep approval disabled for corrupt, unknown-signer or unreviewed records. Offer request re-scan/new view without destroying the previous record.
- Make the mirrored screen readable from the jury table; show unassessed checks rather than an overall safe badge.
- Own key enrolment screens (show own QR, scan peer QR, fingerprint confirmation), approval-role labels and P3 verification screen; services come from B12/B14 and the B01 fake contracts.
- Own the beam scan overlay, strip origin/ticks/zone labels through B11 result types; the camera/geometry owner must not edit ui/.
- Request-another-view writes a small ReviewRequest referencing the immutable capture hash/member, with a note and requested zone. Export it through the same Office Kit/file-picker path; the operator imports it into a pending-request list. Do not expose a no-op request button.

## Acceptance

- [ ] Fixture states include unsigned, capture valid, unknown signer, corrupt, pending review, cancelled biometric, approved and already processed.
- [ ] Cancellation of picker/transfer/review preserves the current record; an old approval cannot be displayed on an edited record.
- [ ] User explicitly chooses a received document; no silent whole-storage permission or arbitrary folder scan.

**Loaner check:** Alwin acts as engineer on P2, receives a real pack through Office Kit, opens it from the system picker and requests a new view before approving a second record.

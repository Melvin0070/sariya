The jury and engineer can trace each accuracy number to a stored observation and revisit previous inspections.

## Ownership and deliverable

Own **ui/numbers/, ui/history/, CSV presentation/export adapter**. You are not alone in the codebase: preserve others' changes. Alwin owns UI, Sabari camera/geometry, Melvin shared types/build/rules/trust. Request a handoff before editing another package or frozen contract.

## Work

- Build against telemetry and record fixtures first; bind B08/B17 data at integration. List local records by member/time/status with reopen and export, no cloud backend required.
- Display p50/p95 stage/backend timings, model hash, actual accelerator, sample counts, measurement mode and uncertainty floor. Empty data is no data, not zero-error success.
- Provide a bench table with measured vs tape c/c, residual, band, within-band result, abstention, distance/stream/family and source. Export CSV with identifiers linking back to evidence.
- Separate calibration observations from held-out evaluation. Label bench/half-scale props and denominator; show abstentions. A small bench table cannot imply general 95% site coverage.
- Show claimed vs measured device usage separately: Sariya can count its own work, not predict the organiser score or reliably measure another app’s foreground minutes.

## Acceptance

- [ ] Known CSV fixture calculates errors/coverage/percentiles correctly; missing truth rows are excluded with counts, not silently treated as perfect.
- [ ] Manual, automatic, synthetic and duplicate records remain distinguishable. App restart preserves history and values.
- [ ] The numbers screen derives from stored samples; no hardcoded demo accuracy/latency values or fictional site visits.

**Loaner check:** Open three real stored records, locate the tape row for one, export CSV and compare its measurement/band to the signed record.

## Cut line / failure branch

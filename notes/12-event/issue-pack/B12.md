# Persist and sign immutable capture evidence with enrolled device keys

A saved record proves which bytes and images the enrolled capture device signed, and survives app updates.

**Owner:** @Melvin0070 · **Phase:** CP2 · **Budget:** 3 focused person-hours (estimate; excludes idle training/download time)
**Control and current gate times:** [CONTROL.md](CONTROL.md)
**Prerequisites / integration dependencies:** [B01](B01.md), [B05](B05.md), [B08](B08.md)
Work against B01 fixtures while a service dependency is being built; acceptance still needs the real service. The control issue defines the explicit manual/gated fallback path. Do not close an unproven automatic feature just because the fallback shipped.

## Ownership and deliverable

Own **record/ canonical payload, storage, capture signing and enrolment**. You are not alone in the codebase: preserve others' changes. Alwin owns UI, Sabari camera/geometry, Melvin shared types/build/rules/trust. Request a handoff before editing another package or frozen contract.

## Work

- Define versioned canonical payload bytes and test vectors; exclude signature envelopes from the capture payload. Bind spec revision, locked values/bands, rulebook/model/calibration hashes, evidence file hashes, manual readings and provenance.
- Persist records atomically; do not write a valid-looking half record after process death or full storage. Keep previous record immutable when corrections create a new revision.
- Generate capture and approval key roles in Android Keystore on separate devices. Try available hardware protection and report actual level; StrongBox absence must not break signing or be called StrongBox.
- Enrol capture/approval public-key fingerprints through a deliberate QR/fingerprint confirmation on the other devices before verification. Keys supplied inside an imported pack are untrusted until enrolled. This proves an enrolled device key, not professional credentials.
- Set up approval-key authentication policy for B14; distinguish biometric cancellation, unavailable enrolment and invalidated key. Never silently substitute the operator key.
- Provide APIs and fake view models for Alwin; no edits to ui/ without handoff.

## Acceptance

- [ ] Same payload yields identical canonical bytes across encode/decode; reject NaN, duplicate/ambiguous fields and unsupported schemas. Changing any bound field/image causes verification failure.
- [ ] Unknown self-signed key shows unknown signer; enrolled capture verifies. Public keys can be shared, private keys never exported.
- [ ] App process restart and same-certificate APK update retain keys/history. Missing image, interrupted save and key invalidation cannot show valid capture approval.

**Loaner check:** Enrol P1/P2 keys on P3, sign a real Lock, update the APK without uninstalling and verify again; try a pack from an unenrolled key.

## Cut line / failure branch

If hardware attestation is unavailable, show actual Keystore backing and omit attestation claims. If signing fails, retain unsigned evidence visibly and do not claim the trust beat.
